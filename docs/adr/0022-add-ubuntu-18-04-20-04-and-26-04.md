# 0022. Add Ubuntu 18.04, 20.04, and 26.04

Status: Accepted
Date: 2026-10-26

## Context

ADR 0019 limited Ubuntu support to 22.04 and 24.04. Fleets still run 18.04 and 20.04 under
Ubuntu Pro, and 26.04 is the current LTS release.

18.04 ships audit 2.8.2 with Python 3.6, and 20.04 ships audit 2.8.5 with Python 3.8. Both keep the
syslog plugin under `/etc/audisp`, as RHEL 7 does, so the code that handles RHEL 7 already covers
them. 26.04 ships audit 4.1.2 with Python 3.14, and audit 4 keeps the rule syntax and the
`rules.d` layout of audit 3 (ADR 0019).

GitHub no longer has runners for 18.04 or 20.04, so neither can run the real kernel test.

## Decision

v1 supports RHEL 7, 8, 9, and 10, and Ubuntu 18.04, 20.04, 22.04, 24.04, and 26.04. Everything else
in ADR 0019 stays.

CI tests the new versions as follows:

- The container install test runs on all three.
- The real kernel test runs on 26.04.
- Molecule runs ansible-core 2.16 against 18.04 and 20.04, and the latest ansible-core against
  26.04. ansible-core 2.16 doesn't support Python 3.14, and the latest release doesn't support
  Python 3.6 or 3.8.

## Consequences

The rules have no real kernel test on audit 2.8.2 and 2.8.5 in CI, so a rule that only those
auditctl versions reject would show up first on a host. The CentOS 7 container test covers audit
2.8.5 rule rendering, and render drops syscalls that a host's tables don't list. Test 18.04 and
20.04 on a VM before a release that changes rule syntax.

When Ubuntu Pro support for 18.04 ends, a later ADR can drop it.
